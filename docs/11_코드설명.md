## 0장. 실행해 보기

준비물은 Ollama가 떠 있고 모델이 있는 것뿐입니다. MCP도, 브라우저도, 별도 서버도 없습니다.

```powershell
ollama list                      # 모델 확인
python demo\11_tool_call.py
python demo\11_tool_call.py "hello 로 test 해줘"
```

실제 출력:

```
======================================================================
[11] Native tool calling   model=qwen3.8-local:27b   host=http://127.0.0.1:11434
질의: hello 로 test 해줘
======================================================================
[1] 도구 호출: test({'a': 'hello'})
123---hello---456                          ← test() 안의 print
[1] 도구 결과: {'ok': True, 'result': '123---hello---456'}
[2] 도구 호출 없음 → 종료
----------------------------------------------------------------------
`123---hello---456`
```

여기서 눈여겨볼 것은 **`[1]` 과 `[2]` 라는 두 번의 왕복**입니다. 모델은 한 번에 답하지
않았습니다. 1회차에서 "test를 부르라"고 말했고, 2회차에서 그 결과를 받아 최종 답을 냈습니다.
왜 그런지가 1장의 주제입니다.

## 1장. 오해부터 풀기 — LLM은 함수를 실행하지 못한다

가장 먼저 버려야 할 그림은 이것입니다.

```
사용자 → LLM → (LLM이 test() 를 실행) → 답변          ← 틀림
```

LLM은 텍스트를 넣으면 텍스트가 나오는 함수입니다. 파일을 열지도, 네트워크를 타지도,
파이썬 함수를 실행하지도 못합니다. **실행은 언제나 우리 코드가 합니다.**

실제로 일어나는 일은 이렇습니다.

```
1) 우리 → 모델 :  "사용자가 이렇게 말했다. 그리고 너는 이런 도구를 쓸 수 있다."
                  (질의 + 도구 명세를 함께 보냄)

2) 모델 → 우리 :  "test 라는 도구를 a='hello' 로 불러 줘."
                  (실행이 아니라 **호출 요청**. 구조화된 데이터일 뿐)

3) 우리         :  실제로 test('hello') 를 실행한다.   ← 여기가 유일한 실행 지점

4) 우리 → 모델 :  "결과는 이거다: {'ok': true, 'result': '123---hello---456'}"

5) 모델 → 우리 :  "결과는 123---hello---456 입니다."   (이번엔 도구 호출이 없음 → 종료)
```

즉 모델이 하는 일은 **"무엇을 어떤 인자로 부를지 판단해서 말해 주는 것"** 까지입니다.
그래서 우리가 짜야 하는 코드는 딱 세 가지입니다.

| 짜야 하는 것 | 이 파일에서 | 하는 일 |
|---|---|---|
| 도구 구현 | `test()` | 실제로 일을 하는 파이썬 함수 |
| 도구 명세 | `TOOL_SCHEMA` | 모델에게 "이런 도구가 있다"고 알려 주는 설명서 |
| 에이전트 루프 | `run_agent()` | 모델의 호출 요청을 받아 실행하고 결과를 되돌려 주는 반복 |

## 3장. 설정 블록과 `OLLAMA_HOST` 함정

```python
MODEL = os.getenv("OLLAMA_MODEL", "qwen3.8-local:27b")
MAX_ITERATIONS = 5
```

`os.getenv(이름, 기본값)` 은 환경변수를 읽되 없으면 기본값을 씁니다. 덕분에 코드를 고치지
않고 모델을 바꿀 수 있습니다.

```powershell
$env:OLLAMA_MODEL = "gpt-oss:20b"
python demo\11_tool_call.py
```

`MAX_ITERATIONS` 는 8장에서 볼 무한 루프 방지 장치입니다.

### 왜 주소를 정규화하는가

```python
def normalize_host(raw: str) -> str:
    host = (raw or "").strip() or "http://127.0.0.1:11434"
    if "://" not in host:
        host = "http://" + host
    return host.replace("//0.0.0.0:", "//127.0.0.1:").replace("//[::]:", "//127.0.0.1:")
```

이 PC의 시스템 환경변수는 `OLLAMA_HOST=0.0.0.0:11434` 입니다. 그런데 `0.0.0.0` 은
**서버가 "모든 네트워크 인터페이스에서 듣겠다"고 선언할 때 쓰는 바인딩 주소**이지,
클라이언트가 접속할 수 있는 주소가 아닙니다. 그대로 접속을 시도하면 `ConnectionError` 가 납니다.

비유하자면 `0.0.0.0` 은 "우리 집 모든 문으로 들어와도 됩니다"라는 **집주인의 선언**이고,
방문자에게 필요한 것은 실제 주소(`127.0.0.1`)입니다. 그 둘을 혼동하는 것이 이 함정입니다.

`or` 를 두 번 쓴 첫 줄도 자주 나오는 관용구입니다.

```python
host = (raw or "").strip() or "http://127.0.0.1:11434"
#      └ raw 가 None 이면 "" 로 ┘         └ 결과가 빈 문자열이면 기본값으로 ┘
```

파이썬에서 `A or B` 는 "A가 참 같은 값이면 A, 아니면 B"입니다. `None`, `""`, `0`, `[]` 이
거짓 취급이라 이런 기본값 처리에 자주 쓰입니다.

## 4장. 도구 본체 — `test()`

```python
def test(a: str) -> str:
    res = "123---" + a + "---456"
    print(f"{res}")
    return res
```

평범한 파이썬 함수입니다. LLM 도구라고 해서 특별한 상속이나 등록 절차가 필요하지 않습니다.

- `a: str` — **타입 힌트**. 파이썬이 강제하지는 않지만 사람과 도구가 읽는 계약입니다.
- `-> str` — 반환 타입 힌트.
- `f"{res}"` — f-string. 중괄호 안의 값을 문자열에 끼워 넣습니다.

`async def` 가 아니라 그냥 `def` 인 점에 주목하세요. 이 함수는 즉시 끝나므로 동기 함수로
충분합니다. 만약 여기서 네트워크를 타거나 파일을 읽는 등 **오래 걸리는 블로킹 작업**을
한다면, 6장의 호출부를 이렇게 바꿔야 합니다.

```python
result = await asyncio.to_thread(test, a)  # 별도 스레드로 떠넘겨 이벤트 루프를 막지 않는다
```

> `async` / `await` / `to_thread` 자체가 낯설다면 [`demo/02_arithmetic.py`](../demo/02_arithmetic.py)
> 를 먼저 실행해 보세요. 순차 실행 → `gather` → `to_thread` 를 한 파일에서 비교합니다.

## 5장. `TOOL_SCHEMA` — 모델이 실제로 보는 것

이 파일에서 가장 중요한 블록입니다. 코드가 아니라 **설명서**이기 때문입니다.

```python
TOOL_SCHEMA: dict[str, Any] = {
    "type": "function",
    "function": {
        "name": "test",
        "description": (
            "문자열 하나를 받아 앞에 '123---', 뒤에 '---456' 을 붙여 돌려준다. "
            "사용자가 어떤 값을 test 해 달라고 하면 반드시 이 도구를 호출한다. "
            "직접 문자열을 만들어 답하지 말고 도구의 반환값을 그대로 사용한다."
        ),
        "parameters": {
            "type": "object",
            "properties": {
                "a": {"type": "string", "description": "가공할 문자열. 예: 안녕하세요"},
            },
            "required": ["a"],
        },
    },
}
```

이 dict는 **JSON Schema** 라는 표준 형식입니다. 구조를 뜯어보면:

| 키 | 뜻 |
|---|---|
| `name` | 모델이 부를 때 쓸 이름. 파이썬 함수명과 같을 필요는 없지만 같게 두는 편이 헷갈리지 않습니다 |
| `description` | **모델이 "언제 이 도구를 쓸지" 판단하는 유일한 근거** |
| `parameters.properties` | 인자별 타입과 설명 |
| `parameters.required` | 반드시 채워야 하는 인자 목록 |

### description이 곧 프롬프트다

초보자가 가장 자주 겪는 증상은 **"모델이 도구를 안 부르고 혼자 답해 버리는 것"** 입니다.
이때 시스템 프롬프트부터 고치려 드는 사람이 많은데, 먼저 볼 곳은 `description` 입니다.

위 설명이 세 문장인 이유가 각각 있습니다.

1. `"문자열 하나를 받아 ... 돌려준다"` — 이 도구가 **무엇을 하는지**
2. `"...하면 반드시 이 도구를 호출한다"` — **언제 부르는지**
3. `"직접 문자열을 만들어 답하지 말고"` — **하지 말아야 할 대안을 미리 막는다**

3번이 특히 중요합니다. `123---` 붙이기는 모델이 도구 없이도 흉내 낼 수 있을 만큼 쉬워서,
막아 두지 않으면 도구를 건너뛰고 자기가 만든 문자열로 답할 수 있습니다. 9장에서 이 문장을
지우고 실행해 보면 차이를 직접 볼 수 있습니다.

인자 설명에 `"예: 안녕하세요"` 처럼 **형식 예시**를 넣는 것도 같은 이유입니다. 날짜라면
`"YYYY-MM-DD 형식"`, 시각이라면 `"HH:MM 24시간제"` 처럼 못 박아야 모델이 엉뚱한 형식을
보내지 않습니다.

## 6장. `call_tool()` — 실패를 예외가 아니라 데이터로

```python
async def call_tool(name: str, arguments: dict[str, Any]) -> dict[str, Any]:
    if name != "test":
        return {"ok": False, "error": f"알 수 없는 도구입니다: {name}"}
    a = arguments.get("a")
    if not isinstance(a, str) or not a:
        return {"ok": False, "error": "인자 a 는 비어 있지 않은 문자열이어야 합니다."}

    return {"ok": True, "result": test(a)}
```

모델이 말한 이름과 인자를 받아 실제 함수로 연결하는 **디스패처**입니다.
도구가 여러 개라면 보통 dict로 관리합니다.

```python
TOOLS = {"test": test, "get_today": get_today}  # 도구가 늘어나면 이런 모양
```

### 여기서 절대 예외를 던지지 않는 이유

가장 중요한 설계 원칙입니다. 이 함수는 **어떤 경우에도 dict를 돌려주고 예외를 던지지
않습니다.** 실패조차 `{"ok": False, "error": "..."}` 라는 **데이터**입니다.

왜냐하면 이 반환값의 최종 독자가 사람이 아니라 **LLM** 이기 때문입니다.

```
예외를 던지면    → 프로그램이 죽는다 → 모델은 아무것도 모른 채 대화가 끝난다
dict로 돌려주면  → 모델이 error 를 읽는다 → "아, a 를 빼먹었네" → 고쳐서 다시 호출
```

즉 에러 메시지는 **모델에게 주는 복구 지시서**입니다. 그래서 `"인자 a 는 비어 있지 않은
문자열이어야 합니다"` 처럼 무엇이 잘못됐고 무엇이어야 하는지를 함께 적습니다.
`"invalid argument"` 같은 메시지는 모델이 읽어도 고칠 수가 없습니다.

`arguments.get("a")` 를 쓴 것도 방어입니다. `arguments["a"]` 는 키가 없으면 `KeyError` 로
죽지만, `.get()` 은 `None` 을 돌려주므로 그 아래 검증으로 흘러갑니다.

## 7장. `chat()` — 모델 호출 한 겹

```python
async def chat(client: AsyncClient, messages: list[dict[str, Any]]):
    kwargs: dict[str, Any] = {
        "model": MODEL,
        "messages": messages,
        "tools": [TOOL_SCHEMA],
        "options": {"temperature": 0},
    }
    try:
        return await client.chat(think=False, **kwargs)
    except TypeError:
        return await client.chat(**kwargs)
```

- **`tools=[TOOL_SCHEMA]`** — 이 한 줄이 "도구를 쓸 수 있다"는 사실을 모델에게 전달합니다.
  매 호출마다 넘겨야 합니다. 모델은 대화를 기억하지 않고, 우리가 보낸 것만 봅니다.
- **`temperature: 0`** — 무작위성을 끕니다. 인자를 파싱하는 데 창의성은 해롭습니다.
  같은 입력에 같은 출력이 나와야 디버깅도 가능합니다.
- **`think=False`** — qwen3 계열은 thinking(속으로 길게 추론하기)이 기본 ON이라 응답이
  느립니다. 도구 호출에는 대개 불필요해서 껐습니다.
- **`try / except TypeError`** — 구버전 `ollama-python` 은 `think` 인자를 모릅니다.
  모르는 키워드 인자를 받으면 파이썬은 `TypeError` 를 냅니다. 그때는 빼고 다시 부릅니다.

`**kwargs` 는 dict를 키워드 인자로 펼치는 문법입니다. `**{"model": "x"}` 는 `model="x"` 와
같습니다. (`*` 가 리스트를 위치 인자로 펼치는 것의 dict 판입니다.)

## 8장. `run_agent()` — 대화가 자라는 과정

이 파일의 심장입니다. 핵심 아이디어는 하나입니다.

> **`messages` 라는 리스트 하나가 계속 자란다.** 모델은 매번 이 리스트 전체를 보고 판단한다.

```python
messages = [
    {"role": "system", "content": SYSTEM_PROMPT},
    {"role": "user", "content": query},
]
```

역할(`role`)은 네 가지가 쓰입니다.

| role | 누가 넣나 | 내용 |
|---|---|---|
| `system` | 우리 | 행동 지침 |
| `user` | 우리 | 사용자 질의 |
| `assistant` | 모델 | 모델의 발화 (도구 호출 요청 포함) |
| `tool` | 우리 | 도구 실행 결과 |

### 루프 본체

```python
for step in range(1, MAX_ITERATIONS + 1):
    response = await chat(client, messages)
    message = response.message
    tool_calls = getattr(message, "tool_calls", None) or []
```

`getattr(x, "이름", 기본값)` 은 속성이 없을 수도 있을 때 안전하게 읽는 함수입니다.
도구를 안 부른 응답에는 `tool_calls` 자체가 없을 수 있어서 이렇게 씁니다.
`or []` 는 `None` 을 빈 리스트로 바꿔 아래 `for` 문이 그냥 0회 도는 효과를 냅니다.

```python
    assistant = {"role": "assistant", "content": message.content or ""}
    if tool_calls:
        assistant["tool_calls"] = [...]
    messages.append(assistant)
```

**모델의 발화를 반드시 messages에 다시 넣어야 합니다.** 넣지 않으면 다음 왕복에서 모델은
자기가 도구를 불렀다는 사실을 모른 채 같은 요청을 반복합니다. 무한 루프의 흔한 원인입니다.

```python
    if not tool_calls:
        return (message.content or "").strip()
```

**종료 조건**: 도구 호출이 없으면 그것이 최종 답변입니다. 몇 번 반복할지는 우리가 정하는 게
아니라 모델이 정합니다. 그래서 이것이 "고정 시나리오"가 아니라 "에이전트 루프"입니다.

```python
    for tc in tool_calls:
        name = tc.function.name
        args = tc.function.arguments
        if isinstance(args, str):
            try:
                args = json.loads(args)
            except json.JSONDecodeError:
                args = {}
        args = dict(args or {})
```

`arguments` 가 dict로 올 때도 있고 JSON **문자열**로 올 때도 있습니다. 모델과 버전에 따라
다릅니다. 문자열이면 `json.loads()` 로 파싱하고, 깨졌으면 빈 dict로 둡니다.
빈 dict로 두면 6장의 검증에 걸려 `{"ok": False, ...}` 가 모델에게 전달되고, 모델이
다시 시도할 기회를 얻습니다. **여기서 죽지 않는 것이 요점입니다.**

```python
for tc in tool_calls:
    ...
    result = await call_tool(name, args)
    messages.append(
        {
            "role": "tool",
            "name": name,
            "tool_name": name,
            "content": json.dumps(result, ensure_ascii=False),
        }
    )
```

- `json.dumps(...)` — `content` 는 **문자열**이어야 합니다. dict를 그대로 넣을 수 없습니다.
- `ensure_ascii=False` — 이것이 없으면 한글이 `안녕` 처럼 이스케이프됩니다.
  모델이 못 읽는 건 아니지만 토큰을 낭비하고 로그를 읽기 어렵게 만듭니다.
- `name` 과 `tool_name` 을 둘 다 넣은 것은 ollama 버전에 따라 읽는 키가 달라서입니다.

### 실제로 messages는 이렇게 자란다

```
[출발]
  1 system  "당신은 도구를 사용하는 에이전트입니다..."
  2 user    "hello 로 test 해줘"

[1회차 후]
  3 assistant  (content 없음, tool_calls=[test(a='hello')])
  4 tool       '{"ok": true, "result": "123---hello---456"}'

[2회차 후]
  5 assistant  "`123---hello---456`"      ← tool_calls 없음 → 종료
```

### 무한 루프 방지

```python
for step in range(1, MAX_ITERATIONS + 1):
    ...
return "도구 호출 횟수 상한에 도달해 중단했습니다."
```

`for` 문이 `return` 없이 끝까지 돌면 마지막 줄에 도달합니다. 모델이 같은 도구를 계속
부르며 끝내지 않는 상황을 상한선으로 끊는 안전장치입니다. 상한에 걸렸다는 사실을
문자열로 알려 주는 것도 중요합니다 — 조용히 빈 답을 주면 원인을 찾을 수 없습니다.

## 9장. 직접 실험해 보기

문서를 읽는 것보다 한 줄 고쳐 보는 게 빠릅니다. 아래는 모두 되돌리기 쉬운 실험입니다.

**실험 1 — description의 마지막 문장을 지운다**

```python
"직접 문자열을 만들어 답하지 말고 도구의 반환값을 그대로 사용한다."  # 이 줄을 지운다
```

모델이 도구를 건너뛰고 스스로 `123---hello---456` 을 만들어 답할 확률이 올라갑니다.
"도구를 안 부르면 도구 설명을 먼저 의심하라"는 말의 근거입니다.

**실험 2 — 인자 이름을 바꾼다**

`TOOL_SCHEMA` 의 `"a"` 만 `"text"` 로 바꾸고 `call_tool` 은 그대로 두세요.
모델은 `text='hello'` 로 부르는데 `call_tool` 은 `a` 를 찾으므로 `{"ok": False}` 가 돌아가고,
모델이 그 메시지를 읽고 재시도하는 모습을 볼 수 있습니다. 6장에서 말한 "복구 지시서"가
실제로 작동하는 장면입니다.

**실험 3 — 도구를 아예 안 준다**

`chat()` 에서 `"tools": [TOOL_SCHEMA]` 를 `"tools": []` 로 바꿉니다.
1회차에서 바로 자연어 답변이 나오고 루프가 끝납니다. 도구 호출이 마법이 아니라
"우리가 보낸 목록"에서 나온다는 것이 분명해집니다.

**실험 4 — messages를 눈으로 본다**

루프 안 `messages.append(...)` 뒤에 넣어 보세요.

```python
print(json.dumps(messages, ensure_ascii=False, indent=2))
```

8장의 표가 실제 데이터로 보입니다. 에이전트가 무엇을 하는지 이해하는 가장 빠른 길입니다.

## 10장. 안 될 때 어디를 보나

| 증상 | 원인 | 확인/조치 |
|---|---|---|
| `ConnectionError` | `OLLAMA_HOST=0.0.0.0:11434` 를 접속 주소로 씀 | 3장. `normalize_host()` 를 지우지 말 것. `curl.exe http://127.0.0.1:11434/api/tags` 로 서버 확인 |
| `model not found` | 모델 태그 불일치 | `ollama list` 로 실제 이름 확인 후 `$env:OLLAMA_MODEL` 로 지정 |
| 첫 실행이 아주 느림 | 27B 모델 VRAM 적재 | 정상. 1분 이상 걸릴 수 있음. `ollama ps` 로 적재 여부 확인 |
| 도구를 안 부르고 혼자 답함 | `description` 이 약함 | 5장·실험 1. 시스템 프롬프트보다 도구 설명을 먼저 고칠 것 |
| 같은 도구를 계속 부름 | assistant 메시지를 messages에 안 넣음 | 8장. `messages.append(assistant)` 확인 |
| 한글이 `안녕` 로 보임 | `ensure_ascii` 기본값 | `json.dumps(..., ensure_ascii=False)` |
| `TypeError: ... think` | 구버전 ollama-python | 7장의 `try/except` 가 이미 처리. 없앴다면 되살릴 것 |
